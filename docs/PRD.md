# Diet Agent - 产品需求文档 (PRD)

> 最后更新: 2026-05-12

## 1. 项目概述

**Diet Agent** 是一款桌面端个人饮食管理应用，帮助用户记录每日饮食、浏览菜谱、追踪营养摄入，养成健康饮食习惯。

**人设**: 猫猫虫 🐛🐱 — 可爱、温暖、陪伴感

## 2. 目标用户

- 个人使用，不设置用户系统
- 通过简单昵称进行个性化展示

## 3. 核心功能

### 3.1 饮食记录
- 记录每日三餐（早餐/午餐/晚餐）及加餐
- 手动选择或搜索食物/菜谱添加到记录中
- 查看每日、每周饮食历史

### 3.2 菜谱浏览
- 初始提供 **50 个菜谱**（从 GitHub 开源菜谱库获取）
- 菜谱内容简洁，包含：菜名、食材、步骤、营养信息（估算）
- 支持搜索和分类筛选

### 3.3 营养追踪
- 基于饮食记录自动计算每日营养摄入（卡路里、蛋白质、碳水、脂肪）
- 简单的每日营养摘要展示
- 饮食记录页提供每周统计报表，展示 7 日摄入分布、记录完成度、目标命中日与本周洞察

### 3.4 个人设置
- 设置昵称
- 设置每日营养目标（可选）

### 3.5 AI 引导式专属计划
- 首页提供主线入口，启动逐步引导式资料采集
- 逐项采集年龄、性别、身高、体重、目标体重、活动水平、饮食偏好等信息
- 每一步即时写入本地数据库，支持后续审计
- 输入异常或前后不一致时，追加追问补充说明
- 资料收齐后生成并保存专属饮食计划

## 4. 技术决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 平台 | 仅桌面端 | 当前需求只做桌面 |
| 数据存储 | 本地存储 (localStorage + Dexie) | 个人使用，无需后端；设置/日志继续走 localStorage，引导式计划与审计记录走 Dexie |
| 用户系统 | 无，仅昵称 | 个人使用，简化设计 |
| AI 识别 | 不做 | 不做拍照识别食物 |
| Claude API | 暂不集成 | 目前先不考虑预算限制问题 |
| 菜谱来源 | GitHub 开源菜谱库 | 有现成资源，无需自建 |
| 技术栈 | Electron + React + TypeScript | 生态成熟，开发快 |
| UI 风格 | Ant Design + 猫猫虫可爱主题 | 功能丰富 + 个性化萌系风格（已确认满意） |

## 5. 技术栈（已确认 ✅）

**Electron + React + TypeScript**

- **前端框架**: React 18 + TypeScript
- **桌面打包**: Electron 33 (electron-vite 2)
- **本地存储**: localStorage + Dexie（轻量直接；结构化计划与审计链使用 Dexie）
- **UI 组件**: Ant Design 5 + 自定义猫猫虫主题
- **构建工具**: Vite 5
- **路由**: React Router 6 (HashRouter)
- **日期处理**: Day.js
- **菜谱数据**: TypeScript 模块，内置 50 道菜谱

## 5.1 UI 设计风格 - 猫猫虫主题（已确认 ✅）

> 用户反馈：「还不错，就按照这个风格来做」

- **色调**: 柔和暖色系（奶油黄 `#FFF8E7`、柔粉 `#FFB6C1`、薄荷绿 `#B8E8D0`、薰衣草紫 `#E8D5F5`）
- **圆角**: 大圆角卡片 (12px~32px)，圆润可爱
- **字体**: Noto Sans SC，亲切温暖
- **装饰**: 猫猫虫 emoji 点缀 + 摇摆/弹跳动画
- **文案风格**: 俏皮、温暖（如「猫猫虫饿饿了」「吃好喝好，健康长大喵~」）
- **卡片**: 半透明毛玻璃背景 + 渐变色统计卡片
- **滚动条**: 粉色定制滚动条
- **背景**: 三色渐变（奶油黄→浅粉→薰衣草紫）

## 6. 不做的事情 (Out of Scope)

- ❌ 用户注册/登录系统
- ❌ 云端同步/后端服务
- ❌ 拍照识别食物
- ❌ 移动端/Web端
- ❌ 社交功能

**核心架构**：用户说话 → LLM API（带 Tool 定义）→ AI 返回工具调用 → 本地执行 → 结果回传 AI → 生成回复

**关键决策**：
- LLM API 选择便宜的（DeepSeek / 通义千问），支持 Tool Use
- API 调用走 Electron 主进程 IPC 通道，安全隔离
- 当前实际落地：由于现有数据仍存于渲染进程 `localStorage`，工具执行与 Agent 控制循环放在渲染进程；主进程负责 API Key 安全存储和远程 LLM 代理，兼顾安全性与现有架构兼容性
