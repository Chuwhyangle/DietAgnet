# AI 引导式计划主线 - 技术设计文档

> 最后更新: 2026-05-12

## 1. 目标

把“测试 API”从首页主线拿开，改成一个真正面向用户的核心入口：

1. 用户点击首页主按钮，启动 `AI 引导式计划制定`
2. 系统一步一步采集用户的基础身体数据和执行背景
3. 每一步都即时落到本地数据库，过程可审计
4. 数据异常或前后不一致时，继续追问补充信息
5. 资料收齐后，生成一份专属饮食计划并保存

## 2. 当前落地方案

### 2.1 首页主线入口

- 首页新增主卡片：`让 AI 一步一步帮你制定专属饮食计划`
- 主按钮状态会根据当前数据切换：
  - `开始制定计划`
  - `继续完善资料`
  - `继续制定计划`
  - `重新制定计划`

### 2.2 引导容器

- 使用抽屉式面板 `PlanBuilder`
- 面板内部包含：
  - 进度与审计信息
  - 当前档案摘要
  - 引导记录（assistant / user / status transcript）
  - 当前问题输入区
  - 结果计划展示区

## 3. 数据存储与审计

### 3.1 数据库

使用现有依赖 `Dexie`，新增本地数据库：

- `diet-agent-planning`

### 3.2 数据表

#### `profiles`

保存当前用户的结构化档案：

- 年龄
- 性别
- 身高
- 当前体重
- 目标体重
- 目标方向
- 活动水平
- 饮食偏好
- 过敏 / 忌口
- 健康备注
- 每日餐次
- 做饭习惯
- 作息安排

#### `sessions`

保存每一轮引导过程：

- `status`
- `createdAt` / `updatedAt`
- `transcript`
- `profileSnapshot`
- `currentStepKey`
- `completedStepKeys`
- `pendingFollowUps`
- `resolvedFollowUpCodes`
- `anomalyNotes`
- `latestPlanId`

#### `plans`

保存最终计划结果：

- 标题
- 摘要
- 热量目标
- 蛋白 / 碳水 / 脂肪目标
- 执行建议
- 注意事项
- 生成来源：`ai` / `local`
- 使用模型名（如有）

### 3.3 审计点

当前实现中，以下信息都可回溯：

- 每轮会话 ID
- 每个问题与用户回答
- 每次自动保存状态
- 每条异常追问
- 生成计划的来源（模型 or 本地兜底）
- 最近多个计划版本的差异

### 3.4 版本审计

当前首页已新增 `计划版本审计` 区域：

- 展示最近 6 个计划版本
- 支持切换查看任意一个版本
- 对比当前版本与上一版本的差异
- 差异内容包含：
  - 热量 / 蛋白 / 碳水 / 脂肪目标变化
  - 用户档案关键字段变化
  - 版本生成来源（AI / 本地）
  - 关联的 session id

## 4. 引导字段顺序

当前主线采集顺序如下：

1. 年龄
2. 性别
3. 身高
4. 当前体重
5. 目标体重
6. 目标方向
7. 活动水平
8. 每日餐次
9. 饮食偏好
10. 过敏 / 忌口
11. 健康备注
12. 做饭习惯
13. 作息安排

其中：

- 前 8 项是强约束的主体信息
- 后 5 项允许跳过，但会写入默认值，保证审计链完整

## 5. 异常追问策略

### 5.1 硬校验

对明显错误或超出合理范围的输入直接拦截，例如：

- 年龄过低 / 过高
- 身高或体重超出极限范围
- 餐次不在可接受区间内

### 5.2 软异常

对“可能合理但需要更谨慎处理”的情况，先保存，再追加追问，例如：

- 年龄处于更敏感区间
- 身高超出常见区间
- 体重超出常见区间
- BMI 偏低 / 偏高
- 目标体重与当前体重差距较大
- 目标方向与目标体重不一致
- 餐次过少或过多

追问会进入 `pendingFollowUps` 队列，并继续写入 transcript。

## 6. 计划生成策略

### 6.1 稳定性优先

为避免模型通道异常导致主线不可用，计划生成采用双层方案：

1. **本地规则兜底**
   - 基于基础代谢 + 活动系数 + 目标方向计算热量
   - 计算蛋白 / 碳水 / 脂肪目标
   - 生成基础执行建议与注意事项

2. **模型增强文案**
   - 如果当前 AI 通道已配置且可调用
   - 用结构化 profile + 本地计算目标请求模型
   - 只让模型负责文案增强，不负责关键数值计算

### 6.2 失败回退

如果模型不可用、JSON 不合规或返回异常：

- 不阻断主流程
- 直接保存本地兜底计划
- 在 transcript 与 plan 结果中记录为 `local`

## 7. 与现有功能的关系

- 该主线独立于悬浮聊天框
- 不依赖 tool-call 才能完成资料采集
- AI 对话诊断仍保留在设置页，用于排查通道问题
- 首页主线以用户真实数据采集为中心，不再把“测试连接”当作核心路径
